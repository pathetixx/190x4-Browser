## 2. Задержка фильтра: Кинопоиск, 3 списка (easylist + easyprivacy + ruadlist)

Сборка движка из 6.6 МБ правил — 144 мс. Заблокировано 243 запроса.

| | p50 | p95 | p99 | max | суммарно за загрузку |
|---|---:|---:|---:|---:|---:|
| холодный кэш | 30.8 мкс | 162.2 мкс | 802.9 мкс | 4656 мкс | 18.5 мс |
| прогретый | 29.1 мкс | 82.9 мкс | 178.8 мкс | 259.5 мкс | 7.2 мс |

Первый прогон дал p99 = 643 мкс и был засчитан как «резать синхронную схему».
Это оказалось артефактом измерения: adblock-rust компилирует регулярки лениво,
при первой встрече. Второй проход по той же странице (`Reload`) показывает
установившийся режим — худший единичный вызов 0.26 мс, вся страница стоит 7 мс
на UI-потоке.

**Вывод: синхронный матчинг в `WebResourceRequested` остаётся.** Кэш решений по
(домен, тип) не нужен. Пороговые значения в спайке переписаны: смотреть на
прогретый проход, суммарную цену за загрузку и худший единичный вызов, а не на
p99 холодного старта.

## 3. DRM

Проба EME (Кинопоиск, UA — обычный Edge 152, не WebView2):

| система | default | SW_SECURE_CRYPTO | SW_SECURE_DECODE | HW_SECURE_ALL |
|---|---|---|---|---|
| Widevine | ok | ok | ok | NotSupportedError |
| PlayReady | ok | ok | ok | **ok** |
| ClearKey | ok | — | — | — |

Воспроизведение проверено глазами: **видео на Кинопоиске играет**.

**Вывод: продуктовая часть жива.** Widevine доступен на программных уровнях
(L3), аппаратный путь есть через PlayReady — на Windows кинотеатры ходят
именно через него. Отсутствие Widevine HW_SECURE_ALL означает лишь потолок
качества там, где сайт требует L1.

Грабля измерения, стоившая прогона: `ExecuteScript` не ждёт промис и
сериализует его как `{}`. Асинхронная проба обязана отдавать результат через
`postMessage` + `WebMessageReceived`.

## 4. Первый живой запуск приложения

Собранный `x4-browser.exe`, окно 1456×909, монитор 96 dpi (масштаб 100%).

Состав процессов нашего экземпляра (после отсечения чужой группы WebView2,
которая уже жила на машине):

| роль | штук |
|---|---:|
| browser | **1** |
| gpu-process | 1 |
| crashpad-handler | 1 |
| utility | 2 |
| renderer | 2 (chrome + страница) |

**Один browser-процесс на chrome и вкладку** — Environment, взятый у Tauri,
действительно общий. Это же и объясняет, почему первые прогоны показывали «2
browser»: в выборку по маске командной строки попадала посторонняя группа
WebView2 (у неё другой родитель).

Проверено вживую: страница новой вкладки рисуется поверх chrome, командная
палитра убирает страницу с экрана и рисуется над ней, боковая панель отжимает
страницу и едет синхронно с анимацией, Ctrl+K работает при фокусе на странице.

Не проверено: масштабирование на 150% DPI — на этой машине негде.
