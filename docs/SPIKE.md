# Спайк: три замера

> Результаты первого прогона — [measurements/2026-09-12.md](measurements/2026-09-12.md).

Спайк отвечает на вопросы, от которых зависит архитектура. Он **не** использует
Tauri: меряет движок, а не обвязку. Собирается только под Windows.

```bash
cargo build --release -p browser190x4-spike
```

Отчёты пишутся в `spike-out/*.json` и дублируются в stdout.

## 1. Память на 20 вкладках

```bash
browser190x4-spike memory --tabs 20 --settle 20
```

Открывает вкладки в одном Environment (тяжёлые сайты: Кинопоиск, VK, YouTube,
Озон, Дзен…), делает срезы на 0 / 1 / 5 / 10 / 20 вкладках и суммирует
**private bytes** по всем процессам Environment плюс свой процесс. PID-ы берутся
через `ICoreWebView2Environment8::GetProcessInfos` — это ровно наши процессы, а
не все `msedgewebview2.exe` в системе.

Читать так:

* `steps[0]` — постоянная цена движка (браузерный процесс + GPU);
* `marginal_mb_per_tab` — сколько стоит вкладка сверх этого;
* сравнивать с Edge/Chrome на тех же 20 сайтах (диспетчер задач, сумма по дереву).

Решение: если прирост на вкладку сопоставим с Edge — схема «один процесс + N
контроллеров» подтверждена. Если вдвое хуже — усыпление фоновых вкладок надо
делать сразу, а не «когда-нибудь».

## 2. Задержка фильтра

```bash
browser190x4-spike adblock --url https://www.kinopoisk.ru/ --lists src-tauri/lists
```

Гоняет реальную загрузку страницы через тот же `Guard`, что в проде, и снимает
перцентили времени `check` по каждому запросу.

Замер идёт в два прохода: первая загрузка (в неё попадает прогрев кэша
скомпилированных регулярок) и повторная (`Reload`) — установившийся режим.
Решение принимается по **прогретому** проходу; холодный нужен, чтобы понимать
цену первых секунд после старта.

Пороги: p99 ≤ 100 µs и худший вызов ≤ 1 мс — проходит без оговорок. Иначе
смотрим суммарную цену за загрузку: до 50 мс на UI-поток приемлемо (это меньше
трёх кадров, размазанных по всей загрузке), до 150 мс — нужен кэш решений по
(домен, тип), выше — выносить матчинг за UI-поток.

В отчёте `verdict` уже содержит вывод по этим порогам.

Если p99 окажется плохим, первый подозреваемый — `Mutex` вокруг кэша
скомпилированных регулярок внутри adblock-rust (см. комментарий в
`crates/browser190x4-adblock/Cargo.toml`): он не контендится, но каждый `check` всё равно
берёт лок.

## 3. DRM

```bash
browser190x4-spike drm --url https://www.kinopoisk.ru/
```

Два шага:

1. **машинный** — EME-проба: `requestMediaKeySystemAccess` по Widevine,
   PlayReady и ClearKey на четырёх уровнях robustness (включая
   `SW_SECURE_DECODE`, который спрашивают российские онлайн-кинотеатры);
2. **глазной** — окно остаётся открытым 3 минуты: надо руками запустить
   трейлер и увидеть, играет ли он.

Второй шаг обязателен. «CDM на месте» и «сайт отдал поток» — разные
утверждения: сайт смотрит ещё и на User-Agent, и на то, не считает ли он среду
небезопасной. Поэтому в отчёт кладётся и `user_agent`.
